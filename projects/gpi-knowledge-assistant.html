GPI Knowledge Assistant

RAG-based Q&A over HSBC's internal GPI documentation — institutional knowledge made self-serve

Platform HSBC Technology 2025–2026

Context

The Problem

📁
Documentation spread across multiple repositories HSBC-specific GPI rules, procedures, and circulars are stored in disconnected systems. There's no single place to search across all of them.
🧠
Resolution logic held in individual memory Experienced investigators carry corridor-specific rules and escalation paths in their heads. This knowledge is not searchable and not transferable.
🔄
Knowledge lost on rotation, slow onboarding When investigators rotate out, the team loses institutional memory. New investigators spend weeks learning rules that should be instantly accessible.

Product

The Solution

  • An AI-powered Q&A interface where investigators ask plain-English questions and receive accurate, cited answers.
  • Answers drawn exclusively from HSBC-specific GPI documentation — procedures, circulars, SLA rules, corridor guidelines.
  • Every answer includes source citations so investigators can verify and trust the output.
  • Out-of-scope questions return a clear not-found response — no hallucination, no guessing.
"What is the SLA for a GPI recall in the USD/INR corridor?"
"What are the grounds for rejecting a gCov payment at HSBC?"
"What is HSBC's escalation path if a beneficiary bank doesn't respond within 5 business days?"

Walkthrough

How It Works

01
Ingest 15–20 HSBC GPI PDFs and procedure documents using pdfplumber — circulars, corridor guidelines, SLA rules, escalation procedures.
02
Index into a structured knowledge base — documents are chunked, embedded, and stored for fast semantic retrieval.
03
Investigator asks a plain-English question via the Q&A interface — no query syntax, no keyword matching required.
04
System searches against indexed documents using semantic similarity — retrieves the most relevant chunks across all ingested sources.
05
LLM synthesises a cited answer — response includes the answer and the source document(s) it was drawn from. No external vendor dependency, no new infrastructure.
